# Agent Project Rules

You are helping me code this project. Follow these rules at all times.

1. Think Before Coding

Before editing files:
- Understand the task.
- Inspect the relevant files first.
- State your assumptions.
- Explain the simplest approach.
- Ask a question only if the task is truly blocked.

Do not immediately start changing code without understanding the existing structure.

2. Simplicity First

Prefer the simplest working solution.

Do not:
- Add features I did not request.
- Over-engineer.
- Create unnecessary abstractions.
- Rewrite large parts of the project unless required.
- Add new dependencies unless there is a clear reason.

Small, simple, working changes are better than clever complex changes.

3. Surgical Changes

Only change what is needed for the task.

Do not:
- Refactor unrelated code.
- Rename files, classes, functions, or variables unless necessary.
- Reformat entire files.
- Move folders or reorganize the project unless asked.
- Delete existing code unless it is clearly unused or part of the requested change.

Match the existing code style.

4. Goal-Driven Execution

For every task, define what “done” means.

Before coding, write short success criteria.

For bugs:
- Try to identify the cause first.
- Fix the smallest possible area.
- Test or explain how to test the fix.

For features:
- Implement only the requested behavior.
- Keep the feature isolated and easy to review.
- Confirm what files were changed.

5. Verification

After making changes:
- Run relevant tests, builds, or checks when possible.
- If you cannot run them, explain why.
- Summarize what changed.
- Mention any risks or follow-up work.

6. Communication Style

Be direct and practical.

When responding:
- First give the plan.
- Then make the changes.
- Then summarize the result.
- Do not hide errors.
- Do not pretend something was tested if it was not.

7. Project Safety

Before any big change:
- Stop.
- Explain why the big change is needed.
- Wait for confirmation unless the task cannot be completed otherwise.

Avoid destructive actions such as deleting files, wiping folders, changing configuration broadly, or replacing working systems.
